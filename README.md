# ROS1_ROS2_communication
Instructions to exchange messages through topics between ROS 1 and ROS 2 machines. For instance, we use this mechanism to send velocity commands to ROS 1 robot from an external Ubuntu 24/ROS 2 machine.

## Requirements
### Computer with ROS 1
First of all, we have to install the rosbridge server in the **ROS 1 machine**:
```
sudo apt update
sudo apt install ros-<ROS-DISTRO>-rosbridge-server
```
### Computer with ROS 2
In the **ROS 2 machine** (client) it is needed to install pip and roslibpy:
```
sudo apt update
sudo apt install python3-pip
pip install roslibpy
```
*Note: In newer versions of Ubuntu (like 24.04), some warnings may arise when trying to install Python libraries globally using pip. You can use the command ```pip install roslibpy --break-system-packages``` at your own risk, or use a Python virtual environment.*

## Usage
### Computer with ROS 1
In the **ROS 1 machine** launch the following file:
```
roslaunch rosbridge_server rosbridge_websocket.launch
```
### Computer with ROS 2
First, download the python script into the **ROS 2 machine** and change the IP of the server (IP of the ROS 1 machine) and the topics to which messages must be published/subscribed. **Read carefully the python script**.
```
git clone https://github.com/Taucrates/ROS1_ROS2_communication
cd ROS1_ROS2_communication
```
Now, execute the python script to start exchanging messages between both computers.
```
source /opt/ros/<ROS2-DISTRO>/setup.bash
python3 bridge_ROS1_2.py
```


## Limitations
This method is only intended for lightweight messages, such as sending velocity commands (```cmd_vel```) or receiving odometry, ultrasonics, or robot/battery state information. Using it with heavy data streams like those generated by cameras (```sensor_msgs/Image```) or LiDARs (```sensor_msgs/PointCloud2```) will likely cause severe network congestion, high CPU usage, and connection drops.
